## Working agreement
1. Restate the scope. Ask about decisions that materially change it.
2. Propose the smallest suitable architecture and explain each component in plain language.
3. Implement the main user journey with loading, empty, success, and failure states.
4. Make the interface accessible and responsive on mobile and desktop.
5. If authentication is in scope, enforce permissions on the server and test that one user cannot read another user's data.
6. Keep secrets server-side. Supply .env.example with names only. Do not commit real credentials.
7. Test the main journey and the described failure case. Report what was and was not verified.
8. Deliver a README with setup instructions, a directory map, environment-variable explanations, and known limitations.
9. Add ARCHITECTURE.md explaining a request from the screen through the server to storage, using actual file paths.
10. Explain each major change so I learn as we build. Tell me how to save the code in GitHub so I can return to Apexelerate.

## Acceptance checklist
- The stated user outcome can be completed.
- User roles and permissions match the brief.
- Main flow works on mobile and desktop.
- Errors produce useful feedback.
- Tests and their results are documented.
- No feature, deployment, or external integration is claimed complete without verification.
